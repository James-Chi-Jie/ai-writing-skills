# 案例：从 CNN 的参数共享解释 RNN

## 创作背景

先写 CNN，再写 RNN，后续计划写 Transformer。用户强调的是神经网络的结构设计思想、参数复用方式和信息流动方式之间的联系，而不是技术名词列表。

## 曾出现的理解障碍

在 RNN 全文和七张配图完成后，作者仍然无法直观理解「RNN 的跨时间参数共享」。这意味着：完整正文与视觉完整性不能等同于教学有效性。

## 更好的解释方式

区分三层：

1. **模型跨句子复用参数**：训练好的神经网络都可以做到，并非 RNN 特有的时间步共享。
2. **同一句子内跨时间步共享参数**：RNN 的每一步重复使用相同的输入权重、循环权重和偏置。
3. **隐藏状态随时间步变化**：状态参与下一步的计算，负责携带当前序列的信息；它不是每个时间步都要单独学习的权重。

用最简示例（有意省略激活函数和偏置）：

`h_t = 0.5 x_t + 0.8 h_(t-1)`，`h_0 = 0`，每一步 `x_t = 1`。

- 第一步：`h_1 = 0.5`
- 第二步：`h_2 = 0.9`
- 第三步：`h_3 = 1.22`

**不变**：0.5 和 0.8 这两个权重，输入 1。
**变化**：传递的状态及计算结果。

这说明：共享规则不等于重复得到相同输出。RNN 的特征是**跨时间步共享状态更新规则，同时传递动态隐藏状态**。

## 写作原则提炼

- 若读者仍困惑于核心机制，优先用可手算的数字示例，不要仅增加术语或装饰性示意图。
- 把写作讨论中的真实理解缺口，纳入正文修订、图示改进和测试集。
- 避免把 RNN 描述为 CNN 加上一个记忆模块；它们分享某些设计思想但并非直接的增量改造关系。

## 后续修订：从“知道传递”到“看到计算”
作者追问历史信息到底如何经数学计算流入后续状态。仅给出 `h_t=f(W_x x_t + W_h h_(t-1)+b)` 不足以回答。
简化模型：`h_t=0.8h_(t-1)+x_t`, `h_0=0`, `x_1=1`, `x_2=x_3=0`，得到 `h_1=1`, `h_2=0.8`, `h_3=0.64`；符号展开 `h_3=0.64x_1+0.8x_2+x_3`，能直接看见最早输入在第三步的贡献。该模型有意省略激活函数、偏置和向量矩阵，不等于实际训练过的 RNN。
计算本身可准确追踪，但神经网络学习到的隐藏状态并不总能简单映射到人类可命名的语义。
