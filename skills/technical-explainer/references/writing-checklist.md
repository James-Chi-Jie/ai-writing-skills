# 技术文章发布前检查清单

## 知识准确性
- [ ] 主问题是否清晰、可回答？
- [ ] 是否区别了教学路径与真实技术演进？
- [ ] 是否出现「只能」「一定」「完全」等容易过度概括的表述？
- [ ] 核心公式的符号、维度、条件和解释是否正确？
- [ ] 例子是否真实支持结论，而非仅看上去相似？

## 教学有效性
- [ ] 是否先让读者感受到问题，再出现术语？
- [ ] 是否明确旧方法能做到什么、不能做到什么？
- [ ] 最难的概念是否至少有一个可运行/可手算的最小示例？
- [ ] 作者能否不看文章用自己的话解释核心机制？
- [ ] 读者是否能够区分参数、输入和中间状态？（如适用）

## 图文结合
- [ ] 每张图是否只承担一项主要教学任务？
- [ ] 图中箭头、符号、位置顺序和计算关系是否准确？
- [ ] 图注是否说明该看什么，而不只是复述标题？
- [ ] 关键机制图是否在批量配图之前审核通过？
- [ ] 是否对照正文逐张检查，避免“图好看但讲不清”？

## 写作协作
- [ ] 是否尊重之前确定的叙事主线和风格？
- [ ] 是否避免对同一个已确认的大纲重复确认？
- [ ] 修订是否解决了用户指出的真实理解缺口？
- [ ] 是否为下一篇留下自然问题，而非强行制造架构继承关系？
