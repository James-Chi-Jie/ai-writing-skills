# 知识教学与教育文章写作检查清单

## 知识准确性
- [ ] 主问题是否清晰、可回答？
- [ ] 是否区别了教学路径与真实技术演进？
- [ ] 是否出现「只能」「一定」「完全」等容易过度概括的表述？
- [ ] 核心公式的符号、维度、条件和解释是否正确？
- [ ] 例子是否真实支持结论，而非仅看上去相似？

## 设计必要性与数据角色
- [ ] 是否先核对读者提出的更简单替代方案是否可行，而不是为引入新技术硬造一个“不可能”？
- [ ] 是否明确区分数学必要条件、架构选择、常见工程约定？
- [ ] 每个“参与计算”的对象究竟参与的是索引、连续数值运算、训练目标定位，还是梯度更新？是否避免混同？
- [ ] 如果替代方案取得相同输入向量，后续计算是否保持一致？若保持一致，是否避免夸大新方案的模型表达能力？
- [ ] 作者的质疑是否真正修复了论证的前提，而不是只在旧结论后加一句限定？

## 教学有效性
- [ ] 是否先让读者感受到问题，再出现术语？
- [ ] 是否明确旧方法能做到什么、不能做到什么？
- [ ] 最难的概念是否至少有一个可运行/可手算的最小示例？
- [ ] 作者能否不看文章用自己的话解释核心机制？
- [ ] 读者是否能够区分参数、输入和中间状态？（如适用）

## 低阅读成本（不是短篇幅）

- [ ] 开头是否尽早交代核心问题、重要性和阅读所得？具体问题是否在前面给出直接答案或清晰的理解路线，而不是故意藏起结论？
- [ ] 全文是否围绕一个主问题推进，并尽量复用稳定例子、控制变量变化？
- [ ] 每段是否承担明确任务：补前提、解释机制、回答子问题、验证结论、说明重要边界或衔接下一步？
- [ ] 是否删除重复结论、装饰性过渡和与当前主问题无关的背景？
- [ ] 是否把核心理解所需的推导留在正文，同时把真正可选的高级细节放到旁注、附录或后续文章？有没有为了简短而跳过关键因果步骤、用术语压缩解释？
- [ ] 相邻技术是否只在说明边界或引出后续问题时简要出现，没有变成技术名词清单？
- [ ] 标题、表格、图和总结是否帮助读者定位与比较，而不是重复表达同一信息？
- [ ] 一个没有耐心的读者扫读标题、开头和小节标题，能否知道文章要回答什么；逐节阅读时，能否知道每节为何存在？

**判断标准：** 不按字数评判。必要时可以写长；目标是减少读者寻找答案、补齐逻辑、切换例子和过滤无关信息的成本。

## 图文结合
- [ ] 每张图是否只承担一项主要教学任务？
- [ ] 图中箭头、符号、位置顺序和计算关系是否准确？
- [ ] 图注是否说明该看什么，而不只是复述标题？
- [ ] 关键机制图是否在批量配图之前审核通过？
- [ ] 是否对照正文逐张检查，避免“图好看但讲不清”？

## 写作协作
- [ ] 是否尊重之前确定的叙事主线和风格？
- [ ] 是否避免对同一个已确认的大纲重复确认？
- [ ] 修订是否解决了用户指出的真实理解缺口？
- [ ] 是否为下一篇留下自然问题，而非强行制造架构继承关系？

## 参与式理解与证据边界
- [ ] 当作者说“不理解”，是否先定位前提缺失/概念混同，而不是重复结论或增加公式？
- [ ] 是否使用固定变量的最小对照，清楚区分总容量与单次输入工作量等不同度量？
- [ ] 作者的真实追问是否转成了正文对应段落的理解验收点，而非原样堆叠问答？
- [ ] 是否区分实际运行、玩具示例与尚未验证的生产结论，注明真实实验的版本和环境？
- [ ] 作者已表明理解或要求继续后，是否避免强制性测验？

## 发布版增补核查
- [ ] 对最关键的能力，是否用数字/程序实际展示其计算机制，且明确哪些部分是简化？
- [ ] 图片内部无“图1”“图2”等编辑编号，真实计算步骤编号仍保留？
- [ ] 图片文件名是否为稳定的语义化名称（如 `token-id-embedding-lookup.png`），而非编辑顺序编号？
- [ ] 插入、移动或删除图片时，是否只调整正文引用位置，不无故重命名未改动图片？

## 故事表达（教学和创作按需使用）

- [ ] 读者能否说清最初的问题，以及最后的理解相比起点发生了什么变化？
- [ ] 每一节是否基于上一节已知信息推进？有没有突然登场的名词或无因果关系的知识列表？
- [ ] 所谓“转折”是否有真实依据？如果读者提出的简单方案其实可行，有没有承认它？
- [ ] 类比、假设场景、最小玩具实验和真实来源事实是否清楚区分？
- [ ] 在去掉悬念、拟人化、形容词后，核心解释仍然成立吗？
- [ ] 是否根据任务长度调整故事密度？短回答与正式对照表不强行使用五幕结构？

如任务的核心是评价现有技术论文、创新性、Benchmark 或传播现象，不使用本写作清单替代研究审查；应转交 [research-analyst](../../research-analyst/SKILL.md)。共享的表达方式以 [storytelling](../../../shared/communication/storytelling.md) 为准。
